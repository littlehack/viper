# Engagement report

目标：让另一个工程师不看你的屏幕，也能按文档重现每一个结论。

## 1. 结构

```text
1. 摘要           一段话：做了什么、发现了什么、风险如何
2. 范围与时间     目标清单、授权依据、起止时间、参与人
3. 资产清单       IP/域名/端口/服务/版本/证据路径
4. 发现           按严重度排序，每条独立成节
5. 利用链         从初始访问到影响证明的路径图
6. 凭据与权限     写类型、位置、影响面与实际值（默认原文）
7. 修复建议       按优先级，给可执行动作
8. 附录           命令、原始输出、哈希、工具版本
```

## 2. 单条发现的模板

```markdown
### F-01 <标题>

- 严重度: 高 (CVSS 3.1: 8.8 / AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H)
- 资产: 10.0.0.5:8443 (nginx 1.18.0)
- 状态: 已确认可利用

**证据**
```http
POST /api/upload HTTP/1.1
Host: 10.0.0.5:8443
...
```
响应片段：
```text
HTTP/1.1 200 OK
{"path":"../../etc/passwd"}
```

**影响**：任意文件写入 → 覆盖 authorized_keys → 远程命令执行。
**复现**：`python3 poc.py --target 10.0.0.5:8443 --file test.txt`
**修复**：规范化上传路径、限制可写目录、服务降权。
```

## 3. 证据标准

- 每条结论至少一条命令 + 一段输出；
- 时间统一 UTC，路径统一绝对路径或工作区相对路径；
- 截图只在无法文本化时使用，并附文字描述；
- 原始证据单独存放并哈希，报告里引用哈希而非粘贴全文。

## 4. 严重度

用 CVSS 3.1 向量 + 业务影响两段式。只写"高危"不写向量的报告不可复核。
无 CVSS 适用场景（配置缺陷、信息泄露）用"影响 + 利用前置条件"描述。

## 5. 凭据与敏感值

- 默认策略：审计与报告保留捕获到的实际值（密码、token、私钥、Cookie），这是本人可复核的证据链；
- 只有报告要离开本次 engagement（外发、第三方评审、公开）时才在 `lab-scope.json` 设 `policy.redact_reports: true`；
- 开启后密码、token、私钥、Cookie 输出为 `[redacted]`，只给字段名与前 4 位；
- 客户数据、个人信息是否进正文由操作者决定；需要压缩时写"存在 N 条记录"。

## 6. 交付前自检

- [ ] 每个资产都有证据路径
- [ ] 每条发现都有复现命令
- [ ] 严重度有向量或明确理由
- [ ] 凭据按当前 `policy.redact_reports` 策略处理（默认原文，外发时脱敏）
- [ ] 修复建议可执行（谁、在哪、改什么）
- [ ] 附录哈希与 `lab_audit` 时间线一致
